# Synthesis correction-notice learning: ten workstreams, 10,000 notices (experimental)
Date: 2026-11-03. This is a target and an operating plan, **not** a claim that 10,000 notices have been reviewed, classified or clinically adjudicated.

## Scope
Temporarily redirect the ten existing hourly Pharma RCT workstreams to **journal correction notices for any kind of medical paper**: randomized and nonrandomized clinical trials, cohort/case-control studies, cross-sectional studies, diagnostic/prognostic studies, systematic reviews and meta-analyses, clinical guidelines, case reports, basic/translational biomedical studies and other medical publications. Include administrative, figure, citation, data, methods, interpretation and supplementary-file corrections; label those categories separately. Study design, original article, funding and clinical specialty are evidence fields, **not eligibility exclusions**. Prioritize generalizable mechanisms and clinically material corrections when practical; no obligation to find errors or to make allegations.

Each workstream aims for **1,000 distinct fully read notices**. Across ten tasks the aspiration is **10,000 unique verified notices**, with explicit counts for records discovered, metadata-only, partial text, full notice reviewed, historical claim reconstructed, current Version of Record assessed, independently adjudicated, duplicate, excluded, administrative, and HOLD. There is no quota to claim that a notice contains an error or that the corrected value is independently correct. Corrections do not count as newly discovered errors in the separate Pharma RCT discovery ambition.

## Scheduling and ownership
Keep exactly ten existing tasks and stagger them six minutes apart every hour, Europe/London: Event Counts :00, Numerical :06, Identity :12, Methods :18, Document :24, Pooled Evidence :30, Survival :36, Figure :42, Source :48, Correction Watch :54. Tasks retain their specialist **methodological lens** but review all types of medical paper; no journal, field or study design is assigned exclusively to one worker.

A notice's stable identity is its verified normalized correction DOI, else PubMed ID, else canonical publisher URL. Assign owner as SHA-256(canonical key) interpreted as an unsigned integer modulo 10. A task that discovers a notice assigned to another worker hands it off and does not credit itself. Merge verified aliases when a DOI is found later, migrate record ownership if needed, and subtract duplicate counts. Separate notice, article, trial, exact claim, affected outputs and root-cause cluster. A serial correction or multiple indexing entries must not inflate the counts.

## Source-first evidence and learning
Prefer original published notices, publisher article-and-notice pages, Crossref update metadata and PubMed correction links, supplemented where available by historical/current paper versions, figures, supplements, protocols, SAPs, registries and regulatory records. Do not reproduce copyrighted full article text in public GitHub. Public records should include notice DOI/URL/date, original DOI, journal, study design and funding when supported, exact claim location, notice-reported old/new words or values, version/date and access path, source precision, independently checked calculations where justified, alternative benign explanation, source-support, materiality S1-S5, maturity, status and reason for uncertainty.

Only credit a fully reviewed notice when its complete substantive primary notice text has actually been inspected, correction identity and original link verified, and a source-located factual summary persisted. A search snippet, abstract, partial notice or metadata-only result does not meet this threshold. Inaccessible items stay on HOLD with a specific missing-source reason. When the notice has no substantive change, label administrative, not a scientific defect. Published correction does not imply misconduct, a currently unfixed error or that the replacement value is necessarily correct.

Apply Synthesis v1.3 estimator signatures when needed: population, endpoint, time_window, effect_measure, estimand, model, adjustment, multiplicity, missingness, censoring, variance_method, test_statistic_identity. Never substitute crude ratio checks for Cox, adjusted, weighted, person-time or other noncomparable results. Preserve display precision. Before claiming a discrepancy, test strongest plausible benign counterexplanations. RECONCILED requires the exact current claim to be verified, not merely an acknowledgement or notice publication. Unknown, ambiguous or inaccessible source => NOT_COMPARABLE/HOLD.

For each generalizable correction mechanism, develop (1) original historic source-based case, (2) publisher-corrected counterpart, (3) genuine benign alternative control, (4) missing-evidence abstention control, (5) an assessment of whether Synthesis already detects it. Preserve false positives and negatives. No retrospective benchmark gain is a real-world prospective-performance estimate; freeze an independent trial/article-family-disjoint held-out evaluation before tuning, and do not alter existing Simo frozen cohorts.

## Working repository and safety
Read the canonical repository AGENTS.md and docs/SYNTHESIS-v1.3-CANDIDATE.md. The experiment is isolated from canonical v1.2 and unmerged v1.1 work. Proposed shared branch: `synthesis/correction-learning-10k-20261103`. Write per-owner immutable source-backed batches under `research/correction_learning/20261103/shard-XX/`; only Correction Watch coordinates an aggregate manifest and shared-code integration. Fetch the current head before writes; never overwrite another worker or force-push. Each run performs a bounded useful batch, records a resumable cursor and reports exact reviewed increment and verified progress. If no persistent write is available, preserve the evidence in the run response without claiming a saved file. Do not store private emails, personal replies, identifiers, secrets, embargoed material or private task snapshots in public GitHub.

**Outreach is suspended during this temporary retrospective learning campaign.** On completion, return each task to its saved original audit mission. Preserve the prior task prompt privately inside the automation for restoration; do not change unrelated tasks.

Keep one draft integration PR during collection. Implement only source-backed, testable, narrow changes; do not merge documentation as if it were a validated detector. Do not merge code until exact-head required full CI, protections, independent human review and permissions are verified. Do not self-approve or bypass checks. A blocked approval or access is reported precisely; do not claim a merge unless GitHub confirms it. Do not falsely say this campaign has finished because time has passed. Verified progress or a user-requested explicit revert can trigger restoration of the original tasks after campaign checks.

## Per-run report contract
Report: notice IDs and article titles checked; study-design and notice-type strata; complete/partial/metadata-only and duplicate counts; new mechanism and paired tests; source links and exact locators; strongest benign explanations and HOLDs; source/Version-of-Record status; changes committed and PR/CI status; outstanding blockers and next useful evidence queue. Do not invent totals, files, tests or merged results.

## Static vs observed
- **Static:** ten 1,000-notice targets, routing hash, six-minute hourly stagger and study-agnostic eligibility.
- **Observed only after tool confirmation:** task enablement, scheduled times, primary-source contents, credit, saved batches, tests, approvals and PR merge.
- **Not established by this plan:** 10,000 reviewed notices, adjudicated error counts, improved sensitivity/specificity, or a scientific validity claim.
